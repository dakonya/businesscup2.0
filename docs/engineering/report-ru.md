## Историческая проверка hosted NVIDIA API

Обе переменные `NVIDIA_API_KEY` и `NVIDIA_MODEL` присутствуют. Проверка загрузки окружения подтвердила, что эффективный ключ берётся из существующего `.env`; перекрывающего значения процесса или другого env-файла нет. Лишнего `Bearer`, пробелов и внешних кавычек не обнаружено. Значения ключа и модели не выводились, `.env` не изменялся и не добавлялся в Git.

В исходном package.json не было команды `npm run smoke`. Добавлен полноценный smoke через настоящий HTTP `/api/coach`: seed 42, горизонт 120000 ms, A = 4 API-реплики и B = 1 максимальная попытка на 20000 ms. Скрипт использует production-сборку и временный локальный сервер, который завершает после проверки. Для опубликованного приложения предусмотрен `INCIDENTLAB_SMOKE_URL`.

Сделано **два реальных POST** к NVIDIA: первый полный smoke и один диагностический запрос, необходимый из-за прежнего слишком общего предупреждения. Ответ NVIDIA: **HTTP 401**, безопасная диагностическая строка: `Invalid JWT serialization: Missing dot delimiter(s)`. Приложение честно вернуло HTTP 200 с `source: rules`; smoke завершился кодом 1 и не засчитал это как inference.

На том этапе это был подтверждённый отказ авторизации до генерации ответа модели. Hosted inference с этим credential не был подтверждён. Таймаут, усечение и ошибка Zod не были причиной того HTTP 401. Повторять запросы с тем же credential без изменения причины прекратили. Ниже описан новый, отдельно разрешённый пользователем self-hosted путь на уже имеющейся Brev VM; другой платный API-провайдер не подключался.

Исправлена различимость безопасных предупреждений: HTTP 401 обозначает ошибку аутентификации, 403 — отказ доступа, 429 — лимит провайдера. Upstream body, значения env и внутренние ошибки не выдаются клиенту. Существенная валидация, лимиты и rules fallback сохранены.

## Диагностика существующей Brev VM и настоящий inference

Пользователь разрешил только машину **incidentlab-coach**, ID **vklyxhkb4**, максимум **$3 из текущих кредитов**, без новых машин и пополнений, с обязательной остановкой GPU после проверки. Работа велась через установленный локальный Brev CLI и его актуальные access metadata. Новые VM не создавались; пополнение не включалось.

Подтверждённые проблемы исправлялись последовательно:

1. Docker Compose 2.32.4 отверг `gpus: all`: `services.inference.gpus must be a list`. В Compose заменено только выделение GPU на официальный `deploy.resources.reservations.devices`, ровно один NVIDIA GPU.
2. NVIDIA runtime находился в режиме CDI, но спецификация отсутствовала: `unresolvable CDI devices nvidia.com/gpu=0`, обнаружено 0 устройств. Штатная генерация Toolkit 1.20.1 с драйвером 565.57.01 падала в `libnvidia-sandboxutils` с SIGABRT. Process-local `--feature-flag=disable-nvsandboxutils` сохранил NVML discovery и создал спецификацию; обнаружены 3 имени одного GPU. Драйвер и Docker не обновлялись и не перезапускались ради обхода.
3. CLI сгенерировал устаревший SSH port 18022; актуальный `GetEnvironment` сообщил 22. Использован временный SSH-конфиг задачи, без переписывания глобального конфига и отключения host-key checking.
4. vLLM 0.10.1 выбрал V0 для NemotronH. В этой версии V0 guided decoding уже удалён: реальные ответы содержали fences либо вымышленные IDs и честно отвергались. В том же закреплённом образе включён документированный экспериментальный V1: `VLLM_USE_V1=1`, FlashInfer, prefix caching выключен. Image, модель, revisions и лимиты памяти не менялись.

Brev использует `nvidia/NVIDIA-Nemotron-Nano-9B-v2`; gateway аутентифицирован, vLLM остаётся на loopback. Каждый запрос передаёт вычисленные исходы обеих веток и разрешённые controls, максимум 8 реальных evidence events на ветку. JSON schema ограничивает evidence IDs точным переданным набором через enum. После генерации сохранены строгие `JSON.parse`, исходная Zod-схема и проверка IDs, ограничения длины, 800 output tokens и 18-секундный deadline. Fences не удаляются, ответы модели не подменяются заготовкой, rules fallback сохранён.

После холодного старта первые структурированные запросы не уложились в deadline во время JIT/компиляции. Это оказался временный холодный путь: после завершения компиляции прямой probe вернул HTTP 200 и `{ "ok": true }`, затем полный demo-run вернул настоящий `source: nvidia`. Успешный полный ответ занял **10,666 с** (upstream 10,562 с, 2838 input / 351 output tokens, finish reason `stop`). JSON schema и IDs прошли проверку, namespaces обеих веток присутствуют. Ручной аудит обнаружил ложную формулировку о сохранении очереди у обеих веток при конечной очереди B = 0 и недоказанное обещание улучшения от следующего эксперимента. После исправления этих формулировок следующие реальные ответы выявили двусмысленное смешение failed/pending и инверсию численного сравнения p95 (394 против 397). Prompt усилен общими правилами: состояния клиентов взаимоисключающие, очереди описываются по веткам, направление численных сравнений проверяется по фактам, следующий эксперимент — гипотеза, а limitations описывают допущения модели без повторного сравнения метрик. Ответы не переписывались и не нормализовались; существенная валидация не ослаблялась. После сокращения повторяющегося prompt выполнена последняя ограниченная проверка: **2026-11-14T15:16:16.326Z**, smoke **exit 0**, `source: nvidia`, **7099 ms**. Схема и IDs корректны, но семантический аудит **не пройден**: summary утверждает рост failures при фактическом B − A = −552; limitations выдумывает постоянное замедление после recovery. Значение `retry-backoff = 0` из следующего эксперимента разрешено metadata сценария и ошибкой не считается. Текст модели не исправлялся и не подменялся. Дальнейшие запросы прекращены. Структурная валидация, реальные IDs и `source: nvidia` доказывают происхождение и формат ответа, но сами по себе не доказывают верность всех смысловых утверждений.

Сохраняемое доказательство — [Brev smoke evidence](evidence/brev-smoke-2026-11-14.json), включая фактический неизменённый ответ модели. Дополнительные безопасные локальные артефакты: `.next/incidentlab-smoke.json` и `.next/incidentlab-brev-provider-proof.json`; значения секретов в них не сохраняются, каталог `.next` в Git не добавляется. Временный HTTPS tunnel подтверждает доступ к gateway, но не является production URL приложения.

Цена проверена до старта: L40S **$1,74/ч** плюс диск 384 GB × $0,000132/GB/ч = **$1,790688/ч** суммарно. Остаток до старта — **$9,33**, после остановки — **$7,92**: наблюдаемое списание **$1,41**, `topUpAmount = 0`. Биллинговый ledger может запаздывать, поэтому $1,41 не объявляется окончательным charge. Защитный таймер, взведённый до запуска VM, завершился со статусом `stopped`, причиной `requested` и длительностью **3058 с**. Даже верхняя оценка по этому полному интервалу и суммарной ставке — **не более $1,53**, ниже разрешённых $3. Пополнений и новых VM не было.

**Остановка подтверждена:** контейнеры остановлены (exit 0), локальный `brev stop` завершился exit 0, затем актуальный `GetEnvironment` для ровно **vklyxhkb4 / incidentlab-coach** подтвердил **STOPPED** около 15:18 UTC 14 ноября 2026. GPU не оставлен работающим. Диск и cache сохранены; хранение существующего диска может продолжать тарифицироваться после остановки compute. Автоматический повторный запуск VM не добавлялся.

# Отчёт по backend IncidentLab

Дата: 14 ноября 2026, часовой пояс команды Asia/Almaty.

## Реализовано

Один Next.js App Router + TypeScript + npm проект в корне репозитория. Общий контракт v1 скопирован без изменения типов. Bootstrap опубликован в `setup/incidentlab`, SHA `78c615b41ac57698beb0426bd36f6594b1a5ba2f`. Рабочая ветка реализации — `feat/engine-coach`; точный итоговый SHA приведён в сообщении передачи и доступен через `git rev-parse HEAD`.

Движок `catalog-slowdown` вычисляет очередь API, ограниченный параллелизм, работу четырёх БД-воркеров, краткое замедление, таймауты и повторы. Реализованы три вмешательства, детерминированный replay, полный trace, временные ряды, ветвление строго до checkpoint и сравнение на одинаковой нагрузке. Метрики различают уникальных клиентов и попытки БД; поздний ответ не восстанавливает потерянный пользовательский результат. Pending не считается провалом.

Доступны `getScenarios`, `simulateRun`, `compareRuns`, `forkRun`, `validateRunSpec`. Движок работает в Node и в изолированном браузерном bundle без server/env зависимостей.

Реализованы `GET /api/health` и `POST /api/coach`. Сервер валидирует журнал, самостоятельно пересчитывает обе ветки, отбирает ограниченные факты, проверяет JSON и evidence ID ответа NVIDIA. Есть подсказки трёх уровней, debrief, честный `source: rules`, ограничения тела, действий, времени, ответа, частоты и параллельных запросов. Ограничитель process-local; распределённой защитой не является.

Секреты не включены в frontend, prompt, логи и Git. NVIDIA вызывается через серверный fetch; альтернативный платный провайдер не подключён. Инструкция и скрипт реального небольшого inference-запроса готовы.

После bootstrap файлы страниц, layout и стилей не менялись. Полезный контекст README сохранён, устаревшие сведения о невыбранной идее заменены. Созданы инженерная документация и примеры передачи фронтенду. Исходный untracked каталог `businesscup2.0/` с вложенным Git не изменён и не добавлен в коммиты. GitHub-репозиторий проверен как публичный; main не изменён.

## Реальный demo-run

Seed **42**, горизонт **120 000 ms**, вмешательство на **20 000 ms**. Обе ветки получают **960** уникальных клиентов.

| Метрика | A: API replicas = 4 | B: max attempts = 1 |
| --- | ---: | ---: |
| Успех | 120 | 709 |
| Провал | 800 | 248 |
| Pending | 40 | 3 |
| Попытки БД | 2 588 | 987 |
| Повторы | 1 632 | 27 |
| Конечная очередь БД | 1 355 | 0 |

Разница B − A: **+589** успешных ответов, **−552** провала, **−1 601** попытка БД. Это результат модели, а не универсальная рекомендация для production. B сохраняет 248 провалов: прошлые результаты не переписываются.

В последнем локальном запуске пара replay заняла **66,83 ms** без сериализации; ранее измерены 32,81–71,25 ms. Это наблюдения Node на текущей машине, не гарантия производительности браузера. Trace содержит 12 130 и 5 466 событий; JSON-представления — около 2,56 и 1,11 млн символов. Фронтенду переданы рекомендации фильтровать trace и не пересчитывать на каждом кадре.

## Оставшиеся границы и блокеры

1. Отсутствуют `NVIDIA_API_KEY` и `NVIDIA_MODEL`. Реальный hosted inference не подтверждён; работает rules fallback. Ключ нужно задать только в серверном окружении и затем выполнить smoke.
2. Полноценный интерактивный frontend, localStorage и браузерный пользовательский сценарий находятся в зоне frontend-участника. Текущая главная страница — scaffold для интеграции.
3. Production URL не создан. В `operations.md` описаны stateless-деплой и проверка доступа жюри без логина/preview protection. Новые платные сервисы не создавались.
4. Визуальный smoke ограничен недоступностью браузерного инструмента. HTTP production smoke и проверка браузерного импорта движка пройдены.

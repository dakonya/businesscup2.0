# Frontend handoff — IncidentLab

Дата проверки: 14 ноября 2026. Ветка: `feat/ui-demo`. Основа: backend `83812c6` из `feat/engine-coach`, bootstrap `78c615b`. Интерфейс полностью переведён на русский по уточнению пользователя. Контракт v1 и расчёты прежние. В серверных facts/provider изменены тексты, языковая инструкция и проверка русскоязычного ответа ИИ; общие зависимости и конфиги прежние.

## Что реализовано

- Стартовая область, карточка «Замедление каталога», собственная SVG-монограмма IL. Интерфейс на русском, системные шрифты, отметка Учебная симуляция.
- Единое рабочее пространство: модельные часы, пауза и воспроизведение, скорости 1/2/4/8×, автоматическая остановка на checkpoint из ScenarioDefinition, переход к произвольному времени и «До конца».
- Метрики клиентов отдельно от попыток БД; успешные, неуспешные и ожидающие запросы всегда рядом. График строится из `RunView.series`, схема API → очередь/обработчики → БД использует вычисленные очереди и активные операции. Время ответа подписано как рассчитанное только по успешным запросам.
- История запросов: поиск по ID, фильтры статусов, страницы по 8 запросов и полный связанный trace выбранного запроса, включая timeout/retry/late response.
- Три управления из ScenarioDefinition, одна Intervention на фактическое изменение, журнал решений. Повторный клик по тому же значению не дублирует запись.
- Сохранение и восстановление SavedSession v1. На диск записываются спецификации и курсоры, а не вычисленные trace. Проверка схемы и ограничений движка защищает от повреждённых или устаревших данных.
- У вкладок отдельные снимки localStorage. Ключ ротируется при mount; reload и дублирование наследуют предыдущий снимок, дальнейшие записи независимы. Отказ storage оставляет практику доступной в памяти с объяснением.
- «Назад и новая ветка» сохраняет A и создаёт B с тем же seed и только `atMs < checkpointMs`. Просмотр прошлого блокирует редактирование до явного создания новой ветки; просмотренный горизонт хранится как отдельная вкладочная UI-метаинформация.
- «Сравнить попытки» заново проигрывает две спецификации до одинакового конца сценария через compareRuns. Таблица и диаграмма содержат исходы клиентов, попытки, повторы, latency и B−A. Уменьшение attempts не подписано как автоматическая победа.
- Coach работает только через POST /api/coach. Есть «Подсказка» и «Разбор», глубина подсказки, loading, 22-секундный предел ожидания, error/retry и отмена/игнорирование устаревших ответов при смене контекста. Разбор ИИ и Разбор по правилам подписаны по source; warning виден. Текст модели выводится обычным React-текстом.
- Namespaced evidence-ссылки открывают правильную ветку и запрос/системное событие. На телефоне доступны быстрые переходы «Метрики / Запросы / Решение / Помощник».

В production нет preview fixtures или скрытой подмены данных. Все результаты получены из настоящего общего движка.

## Русская локализация

Переведены основной интерфейс, доступные имена, описание кейса, настройки, история событий, сравнение, сообщения сохранения и разбор помощника. Формат чисел — ru-RU, время — с/мс, HTML lang=ru. Сохранённые Attempt A–Z мигрируют в Попытка A–Z без изменения спецификаций. Ответ ИИ без кириллицы в текстовых полях отклоняется и заменяется русским разбором по правилам. Runbook и скриншоты обновлены.

# IncidentLab: сценарий демонстрации

Демонстрация занимает 60–90 секунд. Показываем один кейс **Замедление каталога**, расследование запроса, действие, сохранение A, возврат к той же ситуации, независимую B и сравнение. Интерфейс и реплики для жюри — на русском.

## Подготовка

Используйте Node.js 24 LTS. В корне проекта:

```sh
npm ci
npm run dev
```

Откройте [локальное приложение](http://localhost:3000). Для чистой демонстрации нажмите **Начать практику**, даже если доступна **Продолжить практику**. Новая практика использует проверенный **сид 42** — начальное число для воспроизводимой нагрузки. Регистрация не требуется. Для проекторного показа удобно окно шириной 1440 пикселей; перед выступлением проверьте читаемость на самом проекторе.

Источник времени и доступных значений — `getScenarios()[0]` из движка. В текущем сценарии `checkpointMs = 20000`, `durationMs = 120000`: первая остановка **00:20**, общий горизонт сравнения **02:00**. Фронтенд читает эти значения из определения сценария. Скорость воспроизведения меняет скорость показа модельного времени, а **До конца** рассчитывает тот же прогон сразу до конца.

Помощник работает через серверный `POST /api/coach`. Для реального ответа ИИ бэкенд настраивает `NVIDIA_API_KEY` и `NVIDIA_MODEL` на сервере. Без них тренировка и сравнение работают, а разбор честно подписан **Разбор по правилам**. Не просите жюри вводить ключ. Не помещайте ключ в клиентские переменные или демонстрационные материалы.

## Реплика перед первым кликом

> «IncidentLab позволяет безопасно потренировать первые решения на дежурстве. Я могу исследовать инцидент, проверить изменение, затем вернуться назад и сравнить другое решение на том же потоке запросов».

До расследования не раскрывайте причину инцидента или заранее «правильное» решение.

## Основной проход: 60–90 секунд

| Время выступления | Действие в интерфейсе | Что показать или сказать |
| --- | --- | --- |
| 0–8 с | Нажмите **Начать практику**. Оставьте скорость **4×**. Дождитесь автоматической остановки на **00:20** — около пяти секунд показа. | «Пользователи получают медленные ответы и ошибки. Начну с фактов». Покажите отметку о симулируемой среде и остановившиеся часы. |
| 8–23 с | В исследовании запросов нажмите **Ошибки**, затем **Подробнее** у первого запроса. Откройте полную историю событий под таблицей. | Покажите таймаут, связанные попытки и их отметки времени. «Запрос пользователя и попытка обращения к базе данных учитываются отдельно». Осмотр на паузе не продвигает время. Теперь можно объяснить увиденный повтор: он добавляет ещё одну попытку. |
| 23–38 с | Пока часы ровно **00:20**, в группе **Реплики API** выберите **4**. Покажите одну запись в журнале решений. Нажмите **До конца**, затем **Сохранить попытку**. | Это **Попытка A**. Покажите последствия: 120 успешных запросов, 800 с ошибкой, 40 в ожидании. «Моей первой гипотезой было масштабирование API. Теперь я вижу последствия». |
| 38–50 с | Нажмите **Назад и новая ветка**. Убедитесь, что появилась **Попытка B** на **00:20**, а реплик снова **2**. В **Максимум попыток** выберите **1**, затем нажмите **До конца**. | «A сохранена. B начинается в той же контрольной точке, с тем же сидом, до моего первого решения». У B одно новое решение на контрольной точке. |
| 50–65 с | Нажмите **Сравнить попытки**. Покажите таблицу **Сравнение последствий** и общий горизонт **120 с**. | «Одинаковые поток и горизонт: у B на 589 успешных ответов больше и на 552 ошибки меньше. При этом остались 248 запросов с ошибкой и 3 в ожидании». Покажите попытки обращения к БД рядом с исходами запросов пользователей. |
| 65–90 с | Нажмите **Разобрать сравнение**. Покажите источник ответа и откройте ссылку **Попытка B · Событие…**, если она доступна. | «Разбор опирается на вычисленные результаты и события, которые можно проверить». При `source=nvidia` виден **Разбор ИИ**, при `source=rules` — **Разбор по правилам** и предупреждение. Ссылка открывает события нужной ветки. |

Если нужно показать плавное развитие последствий, вместо **До конца** для A выберите скорость **8×** и запустите воспроизведение кнопкой с треугольником. От 20 до 120 секунд модельного времени это занимает около 12,5 секунды показа. Для B используйте **До конца**, чтобы уложиться в общий лимит. Дополнительная анимация не меняет расчётные результаты.

## Проверенные результаты движка

`npm run demo` воспроизводит этот эксперимент настоящим движком. Действия выполняются ровно на 20000 мс, общий горизонт — 120000 мс, сид — 42:

| Показатель | A: реплики API = 4 | B: максимум попыток = 1 | B − A |
| --- | ---: | ---: | ---: |
| Уникальные запросы пользователей | 960 | 960 | 0 |
| Успешные запросы | 120 | 709 | +589 |
| Запросы с ошибкой | 800 | 248 | −552 |
| Запросы в ожидании | 40 | 3 | −37 |
| Попытки обращения к БД | 2 588 | 987 | −1 601 |

У A на контрольной точке одно действие `set-api-replicas: 4`. У B сохранена только история строго **до** контрольной точки; действие A ровно на этой точке не переносится. Новое действие B — `set-max-attempts: 1`. Остальные настройки остаются исходными из сценария: 2 реплики, максимум 3 попытки, задержка повтора 50 мс, кроме изменённого параметра соответствующей ветки.

Это результаты ограниченной симуляции данного кейса. Уменьшение числа попыток само по себе не определяет лучший исход; показывайте успешные запросы, запросы с ошибкой и в ожидании вместе. Ожидание не считается ошибкой. Задержка p95 описывает только успешные ответы. Не превращайте эти результаты в универсальный совет по рабочей инфраструктуре или оценку готовности к дежурствам.

Если числа отличаются, проверьте сид, время действия, журнал обеих веток и общий горизонт. Начните чистую практику и повторите шаги. Не подменяйте значения в графике или таблице вручную.

## Если помощник не ответил

Дождитесь ограниченного ожидания; клиент прекращает запрос примерно через 22 секунды. При ошибке доступна кнопка **Повторить запрос**. Основные воспроизведение, история запроса, ветвление и сравнение остаются доступны.

Если сервер вернул **Разбор по правилам**, покажите этот источник и предупреждение как есть. Если HTTP-запрос завершился ошибкой, завершите демо на вычисленном сравнении: «Тренировка и сравнение работают независимо от помощника». Повторный запрос — по кнопке, без циклических попыток во время выступления.

## Сохранение и повторная демонстрация

**Сохранить попытку** сохраняет журнал и позицию времени в браузере. После перезагрузки нажмите **Продолжить практику**. Вкладки сохраняют независимые снимки; изменения во второй вкладке не должны переписывать активную попытку первой. Повреждённое сохранение показывает сообщение с возможностью начать новую практику.

Для следующего чистого прохода используйте **Новая практика**. Если демонстрируете уже сохранённые A/B, прямо скажите: «Это сохранённые попытки одного воспроизводимого прогона». Пользователь по-прежнему может начать новую практику и выбрать собственные действия.

Резервное видео записывайте с работающего продукта после проверки прохода. Этот сценарий не заменяет видеозапись и не подтверждает проверку на физическом проекторе.

## Проверки перед сдачей

```sh
npm run demo
npm run typecheck
npm test
npm run build
```

Для проверки готовой сборки после успешного завершения сборки:

```sh
npm start
```

Браузерная проверка выполняется отдельно от проверки результатов движка. Финальный отчёт о выполненных проверках и обнаруженных ограничениях ведётся отдельно; наличие этого сценария само по себе не означает, что браузерный проход уже завершён.

Необязательный скрипт проверки — `tests/ui/browser-flow.mjs`. Он использует установленный Chrome и внешнюю установку Playwright; зависимость не добавляется в `package.json` приложения. Запустите сервер, затем выполните:

```sh
node tests/ui/browser-flow.mjs
```

Если Playwright не доступен через обычное разрешение модулей, задайте `INCIDENTLAB_PLAYWRIGHT_MODULE` как импортируемый путь к внешнему установленному модулю. На Windows для абсолютного пути используйте `file:///C:/.../playwright/index.mjs`. `INCIDENTLAB_URL` задаёт адрес работающего приложения; по умолчанию используется `http://127.0.0.1:3000`. Не меняйте общий файл фиксации зависимостей ради скрипта проверки.

Скрипт проверяет полный проход, действительные исходы A/B, быстрые повторные клики, сохранение после перезагрузки, независимость вкладок, повреждённое сохранение, явное ветвление при редактировании прошлого, отказ помощника, устаревший ответ и ширину 360 пикселей. Скриншоты рабочего продукта сохраняются в `docs/demo/screenshots/`. Успешный ответ подставного провайдера в тесте не доказывает реальную работу модели NVIDIA.
